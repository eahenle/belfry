# Security and privacy

- **Least privilege:** Gmail `gmail.labels`; Microsoft Graph `Mail.ReadBasic`; GitHub classic PAT `notifications`; Slack `im:read` for an authorized DM; Yahoo IMAP status only; Jira cloud read scope. No write/mark-read APIs in provider modules. Jira's POST requests perform search only.
- **Secrets:** Keychain's generic password items live in the user's macOS login Keychain. The native helper reads/writes secrets through standard input/output, never command-line arguments, environment variables or stdout logs. Serialized OAuth refresh tokens are stored in Keychain. No service ever exports them to the panel. JSON snapshots omit secret_ref and all private adapter settings. An access token is held transiently in coordinator memory while fetching.
- **Filesystem:** `~/Library/Application Support/NotificationWidget/config.json` and `snapshot.json` are created as mode 0600. The parent data directory is created mode 0700 by the macOS installer. Config files might include email addresses, JQL scopes and URLs, but should never contain tokens.
- **Failure:** Exceptions are sanitized for UI/logs; HTTP response bodies are never dumped. Expired credentials render `auth_required` while retaining the old count with timestamp. Unavailable numeric data must not be converted to zero.
- **Dock access:** AX helper asks only whether permission has been granted; it does not automatically request permanent accessibility trust or inspect messages. It walks Dock UI hierarchy for named app icon and `AXStatusLabel`. Grant system Accessibility access only if you accept the local observer's visibility into Accessibility tree. The API is version/locale sensitive.
- **No background data export:** The coordinator talks only to configured official provider endpoints (plus OAuth identity hosts) and writes the latest counts locally. External executables are user-authorized code with same-user privileges; treat them as trusted plugins. No telemetry server or analytics.
- **No browser access:** No Playwright, no DOM scraping, no user session or stored cookie access. Discord account self-automation is deliberately absent.
- **Corporate accounts:** Follow employer/tenant access policy; do not bypass admin-consent restrictions or acquire tokens from work laptop browser caches. If installation requires permissions you don't have, keep that channel disabled.
- **Local verification:** Review `mac/Helpers/Keychain.swift` and `mac/Helpers/DockBadge.swift` before enabling. Building/replacing unsigned/ad-hoc signed helpers may require renewed Accessibility permission. Codesigning for distribution requires separate trusted identity and notarization.
